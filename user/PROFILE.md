# How I work

Claude reads this file in every repo. Keep it short and replace each prompt with your own answer.

## About me

- Role and experience: what I build and how long I've done it.
- What to explain and what to skip: topics I know well, topics I'm learning.

## Conventions

- Languages and style: naming, formatting and patterns I prefer when a repo doesn't decide.
- Commits and branches: message style, branch names, how big a commit should be.
- Tests: what I expect to be tested and how.

## Reviews

- What to flag: the problems I always want to hear about.
- What to skip: nits and preferences I don't want comments on.
- Pull requests: size, description and how I want them split.

## Tone

- Length and format: how long answers should be, when to use lists or tables.
- Questions: when to ask me and when to pick a sensible default and say so.

## Never

- Things Claude never does for me, beyond what each repo's rules say.
